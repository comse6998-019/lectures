3.1Demo, part 1: write a server (notebook)

%%writefile server.py
import sys
from pathlib import Path
from typing import TypedDict
from mcp.server.mcpserver import MCPServer, Context
from mcp.server.mcpserver.exceptions import ToolError

mcp = MCPServer("workspace")

class EditResult(TypedDict):
    path: str
    replaced: int

@mcp.tool()
async def edit(path: str, old: str, new: str, ctx: Context) -> EditResult:
    """Replace one exact occurrence of old with new."""
    await ctx.report_progress(0, 2, "reading")
    text = Path(path).read_text()
    if text.count(old) != 1:
        raise ToolError(f"old must appear exactly once in {path}")
    await ctx.report_progress(1, 2, "writing")
    Path(path).write_text(text.replace(old, new, 1))
    return {"path": path, "replaced": 1}

if __name__ == "__main__":
    mcp.run(sys.argv[1] if len(sys.argv) > 1 else "stdio")
  1. Point at what the SDK derives: the function name becomes the tool's name, the docstring its description, the type hints its input schema, and the return type its output schema (slides 32–33).
  2. A refusal raises ToolError, so its reason reaches the caller. Any other exception reaches the caller as "Error executing tool edit", with the reason removed.
  3. The tool reports progress twice. Over HTTP, those reports become a stream (part 2).
  4. The last line picks the transport: stdio by default, streamable-http when asked.

Takeaway. About twenty lines of Python make a tool that any MCP host can call.

Notes. Pinned to the official Python SDK, mcp[cli]==2.3.0 (the deck's captures used 2.2.0). Checked on 2.3.0: a ValueError arrives as "Error executing tool edit"; a ToolError arrives as "Error executing tool edit: old must appear exactly once in src/limit.py". The rule that a refusal must reach the model as an observation (lecture 4 slide 64) depends on this choice.

3.2Demo, part 2: write a client (notebook)

from mcp import Client, StdioServerParameters

server = StdioServerParameters(command=sys.executable, args=["server.py"])
async with Client(server) as client:
    print(client.protocol_version)                      # 2026-07-28
    tools = await client.list_tools()
    r = await client.call_tool("edit", {"path": "src/limit.py",
                                        "old": "count", "new": "count + 1"})
    print(r.is_error, r.structured_content)
  1. Connect over stdio. The client starts the server as a child process (slides 11–13) and prints the protocol version, 2026-07-28, and the server's name.
  2. list_tools() returns edit, with path, old and new all required (slide 33).
  3. call_tool returns {"path": "src/limit.py", "replaced": 1}. The file reads count + 1.
  4. Leave out old and new: is_error is true, and the message lists the missing fields (slide 25).
  5. Pass an old that does not appear: is_error is true, and the reason comes through.
  6. Start the server over Streamable HTTP in the background and change one line, Client("http://127.0.0.1:8000/mcp"). With a progress callback, "reading" and "writing" print before the result (slide 53).

Takeaway. Changing the transport changes one line of the client. The calls and the results stay the same.

6Recovery, in one slide

The fix and the poll's answer together. Ledgers, where keys come from, and the evidence are week 11.

6.1An idempotency key lets a server spot a retry.

  • The request ID changes on every attempt, because MCP requires a new one when a call is sent again (slide 56).
  • An idempotency key stays the same on every attempt at one operation, so the server can return the first result instead of applying the edit again.
  • MCP has no field for a key, so the key belongs in the tool's own contract, and the server keeps a record of the keys it has handled.
attempt 1   id=7   key=call_7   the server applies the edit; the reply is lost
attempt 2   id=8   key=call_7   the server has seen call_7; it returns the first result

Takeaway. The tool contract makes a retried edit happen once, which answers last week's poll.

Notes. The poll's answer is (c), the tool contract. Li (arXiv 2609.29095, September 2026, a single-author preprint) measured it: offering a key on every write lowered duplicates from 28% to 4%, and agents reported success in 90% of the runs in which they had applied an effect twice. Birrell and Nelson's RPC numbered calls for the same reason (slide 84), and the end-to-end argument (Saltzer, Reed and Clark, 1984) says the guarantee has to be completed at the endpoints. Week 11, partial failure and bounded recovery, covers ledgers, where keys come from, and what happens when a server crashes between applying an edit and recording its key.

7From accounting to admission

Name the turn from the first half to the second, and open with a vulnerability in the tool the students just used.

7.1Admission and accounting.

  • Accounting records, after a call, what happened and how many times: the idempotency key and the trace. Part I ended there.
  • Admission decides, before a call, whether it may start: the host's consent (slide 104), the server's validation (slide 58), a sandbox's policy. Part II is about admission.
  • Week 3 used the same pair for token budgets. Today it applies to tool calls.

Takeaway. Accounting answers "did it happen, and once?" Admission answers "may it start?"

7.2The Inspector itself had a critical flaw.

  • CVE-2025-49596 affected MCP Inspector versions below 0.14.1 and was rated critical (CVSS 9.4).
  • The Inspector's proxy launched stdio commands on request and checked no credentials. Any request that reached it could run a command on the developer's machine.
  • The fix added authentication. The token in the Inspector's URL in the demo is that fix, and the Inspector now binds to 127.0.0.1 by default.

Takeaway. A tool that starts servers can start anything, so it belongs inside the security boundary.

Notes. NVD, CVE-2025-49596: "Versions of MCP Inspector below 0.14.1 are vulnerable to remote code execution due to lack of authentication between the Inspector client and proxy, allowing unauthenticated requests to launch MCP commands over stdio." Some sources give CVSS 3.1 as 9.6. The published exploit reached the proxy from a web page open in the developer's browser; confirm that description against the original researchers' write-up before saying it. Inspector 2.9.0 guards every /api/* route with a bearer token and binds to 127.0.0.1 unless told otherwise (its environment-variables documentation).

9Enforcement outside the agent: OpenShell

One runtime that implements several of slide 8.6's mitigations, read through its own policy files, and the limits of what it can see.

9.1The model selects; something else must enforce.

  • A model selects an action. A process executes it. Neither can be the component that decides whether the action is allowed.
  • A prompt that says "stay in the workspace" states a rule. It cannot enforce the rule (lecture 4 slide 154, answer a).
  • A proxy setting such as HTTPS_PROXY works only if the program honors it. A program can ignore it, clear it, or use its own network library.
  • ATLAS M0037: controls "should be implemented outside the AI agent and should not rely solely on system prompts, model alignment, or the agent recognizing that an action is out of scope."

Takeaway. The check has to sit outside the model and outside the agent's own process.

Notes. The OpenShell source study (guide §1.2, §8.1) states the same distinction. In OpenShell an agent may propose a change to its own policy, and the proposal is approved by a person or by the gateway's rules, which is M0037 in practice. Complete mediation is lecture 4 slide 75.

9.2OpenShell keeps the policy outside the sandbox.

  • OpenShell is an open-source runtime from NVIDIA (Apache 2.0, version 0.1) that runs each agent in a sandbox.
  • Inside the sandbox: the agent and its tools, treated as untrusted. Linux kernel controls limit which files they can open (Landlock) and which system calls they can make (seccomp).
  • Outside the sandbox: a supervisor that holds the policy and the credentials and makes every network decision.
  • The agent's only route to the outside is its connection to the supervisor.

Takeaway. This is ATLAS M0032, segmentation, built from the guard of lecture 4 slide 75.

Notes. M0032's text: "isolate code execution via containers or virtual machines, restrict filesystem and network access, and limit tool invocation rates". Everything said about OpenShell today describes commit be7af99 (October 2026); say "at this commit" when a detail matters. Source: the OpenShell guide, §2 and §7.

Build: Figure 1 of the guide, ~/workspace/imputed/brainstorm/openshell-figures/architecture.svg.

9.3A connection is paused, checked, then relayed.

  1. A tool calls connect(). The kernel pauses the call.
  2. The sandbox reports the destination, the socket, and which program asked, identified by a hash of the running executable.
  3. The supervisor checks host, port and program against the policy. If the connection is allowed, the supervisor opens it upstream and relays the bytes.
  4. For an HTTPS endpoint marked for inspection, the supervisor also reads each request's method and path before forwarding it.
  5. A denied connection returns "access denied" to the program.

Takeaway. Two decisions, made by a process the agent cannot change: may this program connect here, and may this request go through.

Notes. The first decision is at the transport layer (L4: destination and port); the second is at the application layer (L7: method and path). To read HTTPS, the supervisor terminates the client's TLS with a local certificate authority and opens a separate verified connection upstream. Guide §8.3–8.4 and §9.1–9.2.

Build: Figure 5 of the guide, network-request.svg.

9.4A read-only policy for the GitHub API.

version: 1
filesystem_policy:
  include_workdir: true
  read_only: [/bin, /usr, /lib, /proc, /dev/urandom, /app, /etc, /var/log]
  read_write: [/sandbox, /tmp, /dev/null]
landlock:
  compatibility: best_effort
network_policies:
  github_api:
    name: github-api-readonly
    endpoints:
      - host: api.github.com
        port: 443
        protocol: rest
        enforcement: enforce
        access: read-only
    binaries:
      - { path: /usr/bin/curl }
  • Only curl may connect, and only to api.github.com on port 443.
  • read-only admits GET, HEAD and OPTIONS. A POST is refused. A connection to any other host is refused.
  • Delete the line enforcement: enforce and the mode becomes audit: the POST is logged as a violation and goes through.

Takeaway. An inspected request still goes through unless the mode is enforce.

Notes. examples/sandbox-policy-quickstart/policy.yaml from the OpenShell repository, comments removed (Apache 2.0, © NVIDIA; credit it on the slide). Checked against the source at be7af99: a missing enforcement maps to audit (crates/openshell-supervisor-network/src/l7/mod.rs), and the read-only preset is GET, HEAD and OPTIONS (crates/openshell-policy-schema/src/lib.rs, line 1102). Even a GET can have side effects upstream. The preset classifies methods and says nothing about what they do.

9.5An MCP rule matches tool names only.

mcp_server:
  endpoints:
    - host: mcp.example.com
      port: 443
      path: /mcp
      protocol: mcp
      enforcement: enforce
      mcp:
        versions: ["2026-07-28"]
      rules:
        - allow: { method: server/discover }
        - allow: { method: tools/list }
        - allow: { method: tools/call, tool: read_file }
      deny_rules:
        - { method: tools/call, tool: edit }
  binaries:
    - path: /usr/bin/python3.12
  • OpenShell reads the method and tool name of each MCP request over Streamable HTTP, and refuses a request whose Mcp-Method and Mcp-Name headers disagree with its body (slide 50). This is ATLAS M0028 in practice.
  • Arguments are not matched. An allowed read_file receives any path the server accepts, including one outside the workspace (lecture 4 slide 94).
  • Server responses are relayed without MCP parsing. A poisoned description in a tools/list result (AML.T0110.000) and a poisoned result (.002) both pass through.

Takeaway. The runtime can decide which tool runs. It cannot decide whether the arguments are right or the description honest.

Notes. Adapted from "Allow MCP Tools" in docs/how-it-works/policies/network-rules.mdx at be7af99: the docs allow read_status and deny delete_resource, with separate examples for the 2025-11-25 and 2026-07-28 revisions; this slide renames the tools and combines the deny rule with the 2026-07-28 example. Validate the combined file before it goes on a slide. The docs state that tool argument matching is not supported, that server responses and SSE messages are relayed without MCP policy parsing, and that omitting mcp.versions allows only 2025-11-25. The demo's HTTP server (cell 7) is the kind of server this rule governs; a stdio server would run as a child process inside the sandbox, under its file and network rules (an inference from the docs; confirm).

9.6The agent never holds the secret.

  • The agent's environment holds a placeholder. GITHUB_TOKEN is an opaque reference that only the supervisor can resolve.
  • The supervisor puts the real token into a request only when the request passes the network policy and goes to the host, port and path that the credential is bound to.
  • ATLAS case study AML.CS0045: text injected through an MCP tool made Cursor send its configuration files, with their API keys, to an attacker's server (T0083, Credentials from AI Agent Configuration). Under this design, the files would hold placeholders, and the connection to the attacker's server would be refused unless the policy allowed that host.
  • The token's authority remains. The agent can still make any allowed request with it.

Takeaway. Hiding a credential limits where it can be used. What it can do there is unchanged.

Notes. Guide §11.2; docs/how-it-works/providers/profiles.mdx ("opaque workload placeholder"). CS0045 is from the Backslash Security Research Team; Cursor asked the user before running the command, which ATLAS says potentially mitigated the attack; that prompt is M0029. "Would hold placeholders" assumes the keys were managed as OpenShell provider credentials.

Build: Figure 7 of the guide, credential-substitution.svg.

9.7Which control stops this upload?

The sandbox may read the project, and may POST to uploads.example.com, where the team stores build artifacts. A poisoned tool description tells the agent to upload src/. Which control stops the upload?

  1. Landlock, because src/ is not in the writable paths.
  2. The network policy, because the upload is an outbound request.
  3. Nothing in this policy, because reading src/ and posting to the upload host are each allowed.
  4. The credential placeholder, because the agent never holds the upload token.

Notes. The answer is (c). Uploading only needs read access, so (a) does not apply. The upload host is allowed, so (b) admits the request unless the rule restricts the path or the content. The supervisor inserts the real token for an allowed request, so (d) does not stop it. Each permission is reasonable alone; together they allow the data to leave. Keeping the step that reads code apart from the step that uploads is next week's question. Guide §16, exercise 7.

9.8Which control would have stopped Postmark?

Version 1.0.16 of postmark-mcp added the attacker's address as BCC to every email the tool sent (slide 8.5). Which control would have stopped it?

  1. Human in the loop (M0029): a person approves each email before the agent sends it.
  2. Input validation (M0033): the server validates the tool's arguments.
  3. Segmentation (M0032): OpenShell lets the server reach only Postmark's API.
  4. Supply-chain controls: pin the version, verify artifacts (M0014), keep an AI bill of materials (M0023), and review an update before installing it.

Notes. The answer is (d). The person in (a) approves the tool's arguments, and the BCC is added inside the implementation after approval. (b) validates arguments that were correct. (c) admits the request, because the copy left through Postmark's own API, an allowed host; OpenShell's REST rules match method, path and query, and the BCC sits in the request body. Only a control on the update itself catches a change in the implementation. ATLAS 2026.09 maps M0014 and M0023 to AI Supply Chain Compromise (T0010) and has no mitigation mapped to the rug pull (T0109) yet.

Glossary

Host, client, server
In MCP, the application that contains the model loop; the component inside it that holds one connection to one server; and the separate program that exposes and executes tools.
MCP Inspector
The MCP project's developer tool: a host with no model, in which a person chooses each call and reads each request and reply.
stdio, Streamable HTTP, SSE
The two current transports: a child process spoken to over standard input and output; and a server that receives each message as an HTTP POST. A Streamable HTTP server may answer with one JSON message or with a stream of server-sent events (SSE) that carries notifications before the result. The older HTTP+SSE transport is deprecated.
Request ID, idempotency key
An identifier for one message, new on every retry; and an identifier for one operation, the same on every attempt at it.
Admission, accounting
The decision before a call whether it may start; the record after a call of what happened and how many times.
ATLAS tactic, technique, mitigation, case study
An attacker's goal; a way of reaching it; a defense mapped to the techniques it counters; a real incident or demonstration written as a sequence of techniques.
Feasible, Demonstrated, Realized
ATLAS's maturity levels for a technique: shown possible in research; shown against a real system; seen in the wild.
Tool poisoning, rug pull
Malicious content in a tool's definition, implementation or responses (AML.T0110); publishing an honest tool and later pushing a malicious update (AML.T0109).
Complete mediation
Every route from the agent to a resource passes a check that the agent cannot skip (lecture 4 slide 75).
Sandbox, supervisor
In OpenShell, the restricted environment in which the agent and its tools run; and the trusted process outside it that holds the policy and credentials and makes network decisions.
Audit, enforce
OpenShell's two modes for request rules: log a violation and let the request through; or refuse it. Audit is the default.
Credential placeholder
An opaque value in the agent's environment that the supervisor replaces with the real credential, only for an allowed request to the endpoint the credential is bound to.
